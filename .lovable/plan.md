## Notes
1. Verified from Google's docs: `Map3DElement` exists in the `maps3d` library with `bounds`, `min-altitude`, `min/max-tilt`, `range` and `mode`. `bounds` limits where the camera can be, but objects outside it still render.
2. Not verified: whether the Lovable-managed browser key is allowed to load photorealistic 3D. The first build step makes one manual test load in the preview; if Google denies it, the 3D view needs your own key.
3. Things you need to check in Google Cloud (only if you use your own key): Maps JavaScript API and Map Tiles API enabled, billing on, and the key's allowed websites including www.usop.in and the lovable.app domains.
4. Not verified: whether photorealistic 3D covers Chennai. Coverage is patchy outside big metros, so step 1 is a manual check of the 10 slot areas.
5. Not verified: the 3D SKU name and price. They'll be confirmed on Google's pricing page before the flag is turned on.
6. Not verified: custom SVG marker content and the theme behaviour on 3D tiles. Both get confirmed in the prototype.
7. The privacy guarantee rests on the data: locked users never receive exact coordinates, so camera limits only add a second layer, not the primary protection.
8. No dependency changes: the `@types/google.maps` package already in the project should include the 3D types; if it doesn't, a small local type file covers the gap.
9. Nothing published. Payment, booking and database code is untouched.
